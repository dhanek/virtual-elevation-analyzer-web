## Top 3 Priority Fixes

1. **Duplicate inline color arrays in gpsLapPlots.ts and outAndBackPlots.ts** -- A user who customizes the palette in `shell/multiSegment/shared.ts` will see inconsistent colors on VE plots because `renderGpsLapVEPlots` (gpsLapPlots.ts lines 204-214) and `buildOutAndBackMultiSegmentSeries` (outAndBackPlots.ts line 278) maintain their own hardcoded arrays instead of importing `MULTI_SEGMENT_COLORS`. Replace both local arrays with `import { MULTI_SEGMENT_COLORS } from '../multiSegment/shared'` and use the imported constant.

2. **Off-spec panel background colors #f5f5f5 and #f9f9f9 in extracted templates** -- The UI-SPEC declares `#f7fafc` and `#f8f9fa` as the secondary panel backgrounds. The closing-error div in `renderOutAndBack.ts` (line 414) uses `#f5f5f5`, and both `renderGpsLap.ts` (line 599) and `renderOutAndBack.ts` (line 421) use `#f9f9f9` for the `.ve-parameter` block. While visually subtle, these are literal deviations from the color contract. Change to `#f7fafc` to match the spec and the `ve-lap-summary` block already using the correct value.

3. **Non-spec font sizes 0.9rem and 0.85rem in inline styles** -- The UI-SPEC declares four sizes: 1rem (body), 0.875rem (label), 0.8rem (small detail), and 1.5rem (h2). The "Export All Results to CSV" button in both GPS-lap (`renderGpsLap.ts` line 558) and out-and-back (`renderOutAndBack.ts` line 383) uses `font-size: 0.9rem`, and the lap summary table (`gpsLapPlots.ts` line 361) uses `font-size: 0.85rem`. These sit between declared steps. Change `0.9rem` to `0.875rem` and `0.85rem` to `0.875rem` to align with the declared label size.

## Detailed Findings

### Pillar 1: Copywriting (4/4)

All copy specified in the UI-SPEC Copywriting Contract is present and exact:

- `'Missing data for GPS lap VE update'` -- `shell/gpsLap/updateGpsLap.ts:32` (log.error, not user-visible, matches spec)
- `'Missing data for Out and Back VE update'` -- `shell/outAndBack/updateOutAndBack.ts:39` (log.error, not user-visible, matches spec)
- `'Calculating VE for each lap...'` and `'Calculating VE for out-and-back sections...'` -- appropriate contextual loading messages
- `'Recalculating VE with new parameters...'` -- consistent in both update modules
- `'No valid laps to analyze'` surfaced via `services.showError` -- appropriate empty-state message when GPS detection finds no processable laps

No generic labels ("Submit", "Click Here", "OK", "Cancel") were found in the new modules. The tab label strings ("VE", "Wind", "Power", "VD") are generated by the DOM template code in `renderGpsLap.ts` and `renderOutAndBack.ts` which was lifted verbatim, preserving exact labels.

Score rationale: Contract fully met. No regressions in copy; no new generic labels introduced.

### Pillar 2: Visuals (3/4)

**Preserved correctly:**
- Visual hierarchy of the GPS-lap and out-and-back panels is intact. Section structure (tabs, plots, parameter controls, action footer) mirrors the pre-extraction layout.
- `showError` is routed through `services.showError('No valid laps to analyze')` giving user-visible feedback on the primary failure path.
- Loading states (`showLoading`/`hideLoading`) frame every async operation in both render and recalculate paths.

**Finding -- Duplicate color palettes break single-source-of-truth for the Plotly trace colors:**
- `gpsLapPlots.ts` lines 204-214: local `lapColors` array with 8 entries
- `outAndBackPlots.ts` line 278: local `colors` array with 7 entries (missing `#bcf60c` lime)
- Both arrays duplicate `MULTI_SEGMENT_COLORS` from `shell/multiSegment/shared.ts`
- The out-and-back array is one entry shorter, meaning lap 8+ will differ between modes
- `gpsLapPlots.ts` already imports and uses `getMultiSegmentColor` for wind/power/vd plots (lines 389, 411, 433) but falls back to the local array for the primary VE plot. This creates inconsistent coloring of lap 8 between the VE tab and the Wind/Power/VD tabs within GPS-lap mode.

No accessibility regressions: icon-only buttons were not introduced; all buttons retain text labels.

### Pillar 3: Color (3/4)

**Preserved correctly:**
- Accent `#4363d8` usage is confined to its declared elements (section badges, heading borders, analyze buttons, active tab, spinner) -- the CSS is unchanged and the new modules use CSS class names (`primary-btn`, `secondary-btn`, `ve-tab-button`) that map to these defined styles.
- Error color `#c53030` is used only through existing CSS rules; no new inline error color was introduced.
- GPS marker active `#ff6b00` is unaffected (GPS detection UI helpers remain in `main.ts`).

**Findings:**

1. `#f5f5f5` at `renderOutAndBack.ts:414` -- closing-error container background. Spec declares `#f8f9fa` for secondary panel backgrounds. `#f5f5f5` is off-spec (darker grey).

2. `#f9f9f9` at `renderGpsLap.ts:599` and `renderOutAndBack.ts:421` -- `.ve-parameter` block background. Spec declares `#f7fafc` (cool white). `#f9f9f9` is a warm grey, visually distinct in side-by-side comparison.

3. `#ddd` at `renderGpsLap.ts:599` and `renderOutAndBack.ts:421` -- `.ve-parameter` border. Spec declares `#d4d4d4` as card border; `#ddd` is close but is a shorthand hex (`#dddddd = rgb(221,221,221)`) vs `#d4d4d4 (rgb(212,212,212))`. Slight off-spec deviation.

All three are verbatim carryovers from the original `main.ts` code that predates the UI-SPEC. The phase contract required preservation, so these are documentation gaps in the original spec rather than extraction regressions. Flagged for future CSS consolidation.

Hardcoded multi-segment palette colors (`#4363d8`, `#e6194b`, etc.) in the Plotly trace arrays are plot data colors, not UI surface colors; this is correct usage for Plotly chart libraries.

### Pillar 4: Typography (3/4)

**Preserved correctly:**
- Body text (1rem / 400) and section headings (h4 at 1rem / 500 for sub-headings) match declared tokens.
- `font-weight: 500` (medium) used for "Air Speed Time Offset" h4 labels -- within acceptable range per spec (spec declares 400 / 300; 500 is a minor addition but pre-existing in the source).

**Findings:**

1. `font-size: 0.9rem` at `renderGpsLap.ts:558` and `renderOutAndBack.ts:383` -- "Export All Results to CSV" button. Spec declares sizes: 1rem, 0.875rem, 0.8rem, 1.5rem. `0.9rem` sits between body and label, not on the scale.

2. `font-size: 0.85rem` at `gpsLapPlots.ts:361` -- lap summary table. Also off-scale; should be 0.875rem (label) or 0.8rem (small detail).

3. `font-size: 0.9rem` at `renderOutAndBack.ts:414` -- closing error div. Same off-scale value.

All three are verbatim lifts from the pre-extraction code. The UI-SPEC was drafted as a preservation contract after the code existed; these are existing inconsistencies now documented. Recommended remediation: normalize to 0.875rem at next CSS pass.

### Pillar 5: Spacing (4/4)

Inline spacing values used in the new modules map cleanly to the declared scale:

| Observed value | Scale token | Usage |
|----------------|-------------|-------|
| 0.5rem | sm (8px) | Tab button gaps, `margin-top`, table cell padding, grid `gap` |
| 1rem | md (16px) | Content padding, h4 margin-bottom in parameter blocks |
| 1.5rem | lg (24px) | `.ve-parameter` `margin-top` |
| 0.25rem | xs (4px) | Not observed inline (covered by CSS class rules) |

Plot margins (`{ t: 40, b: 80/60, l: 60, r: 20 }`) are Plotly-specific pixel values for chart rendering, not UI surface spacing -- these are correctly excluded from the scale audit.

No arbitrary spacing values (`calc()`, unusual fractions, `px`-based inline styles for layout) were introduced. The non-standard GPS marker touch-target padding (0.4rem/0.5rem, noted as exception in spec) is in existing CSS, not in any new module.

### Pillar 6: Experience Design (4/4)

**Loading states:** `services.showLoading(message)` is called at the start of both `showGpsLapVEAnalysis` and `showOutAndBackVEAnalysis`, and at the start of both `recalculateGpsLapVE` and `recalculateOutAndBackVE`. `services.hideLoading()` is called in `finally`-equivalent positions. Coverage is complete.

**Error states:** `try/catch` blocks wrap per-lap and per-section VE calculation loops. Individual lap failures are logged and skipped; the aggregate path calls `services.showError('No valid laps to analyze')` when no laps succeed. Screenshot and recalculate operations also have top-level error handling.

**BEHV-03 (Tab/scroll preservation):** `updateGpsLapVEPlots` re-calls `setupTabSwitching` and then explicitly checks `wind-tab`, `power-tab`, `vd-tab` active state to re-render the correct tab (`updateGpsLap.ts` lines 207-225). `updateOutAndBackVEPlots` uses the same pattern (`updateOutAndBack.ts` lines 238-252). Scroll preservation is achieved implicitly -- the in-place update does not call `scrollTo` or reset `scrollTop`; the verbatim lift from `main.ts` preserves this behavior. User confirmed BEHV-03 in 04-03 browser validation.

**BEHV-04 (Air-speed calibration):** `resolveMultiSegmentAnalysisParams` is imported from `analysis/MultiSegmentSettings.ts` in both render modules and `appState.airSpeedCalibrationPercent` flows through `resolveWindSeries`. Mode-specific wind resolution patterns preserved: GPS-lap passes `windSource` explicitly; out-and-back calls `getSelectedWindSource()` from DOM.

**Disabled states / destructive actions:** No new destructive actions introduced. Existing patterns unchanged.
