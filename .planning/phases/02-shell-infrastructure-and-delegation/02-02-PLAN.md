<objective>
Define shell module interfaces and dependency wiring types so that handleAnalyze can delegate to named, importable functions instead of owning every preparation and rendering detail inline.

Purpose: These types and functions form the SHEL-01 foundation for explicit shell-module delegation. Per D-03, D-05, D-06, main.ts should become a composition root that wires these modules rather than implementing them. Per D-11, prefer function-oriented modules.

Output: A frontend/src/shell/analysis/ directory with typed interfaces, a pure payload-preparation function with tests, named render delegate factories, and a barrel index.ts. This plan creates new files only — it does NOT modify main.ts (that is Plan 02-03's job).
</objective>

Current handleAnalyze flow (main.ts lines 2778-2996):
1. getAnalysisModeHandler(lapDetectionMode) → modeHandler
2. modeHandler.prepareSelection(appState) → selection
3. Validate selection (empty check, fitData check, mode-specific validation)
4. getNormalizedActivityArrays(fitData) → allTimestamps, allPower, allVelocity, etc.
5. resolveWindSeries({ fitData, windSource: 'fit', applyOffset: false }) → defaultAirSpeedOffset, allWindSpeed
6. collectSelectionIndices(selection, allTimestamps) → selectedIndices
7. Filter arrays by selectedIndices → filteredTimestamps, filteredPower, etc.
8. Resolve air density / rho array
9. createVeCalculator({ ... }) → calculator
10. calculator.calculateVirtualElevation(...) → initialResult
11. Construct { filteredData, callbacks: { standard, gpsLap, outAndBack } }
12. modeHandler.render(args) — delegates to mode-specific rendering

Steps 4-10 are the "payload preparation" that this plan extracts into a pure function.
Step 11-12 are the "render delegation" that this plan provides named functions for.

**frontend/src/shell/analysis/prepareAnalysisPayload.ts:**
- Import `PreparedAnalysisSelection`, `FilteredAnalysisPayload`, `LapIndexRange` from `../../modes/analysis/types`.
- Import `ActivityDataLike` from `../../state/AppState`.
- Import `resolveWindSeries` from `../../analysis/WindSourceResolver`.
- Import `collectSelectionIndices` from `../../modes/analysis/AnalysisModes`.
- Import `createVeCalculator` from `../../analysis/VeCalculatorFactory`.
- Import `log` from `../../utils/log`.

- Export interface `PayloadPreparationInput` with fields:
  ```typescript
  fitData: ActivityDataLike;
  selection: PreparedAnalysisSelection;
  getNormalizedActivityArrays: (fitData: ActivityDataLike) => any; // injected dependency
  calculateRhoArray?: (fitData: ActivityDataLike) => number[] | null; // optional injected dependency
  ```

- Export interface `PreparedPayload` with fields:
  ```typescript
  filteredData: FilteredAnalysisPayload;
  initialResult: any;
  selectedIndices: number[];
  defaultAirSpeedOffset: number;
  rhoArray: number[] | null;
  ```

- Export `prepareAnalysisPayload(input: PayloadPreparationInput): PreparedPayload` — a pure function that:
  1. Calls `getNormalizedActivityArrays(input.fitData)` to get allTimestamps, allPower, etc.
  2. Calls `resolveWindSeries({ fitData: input.fitData, windSource: 'fit', applyOffset: false })` to get defaultAirSpeedOffset and windSpeed array.
  3. Calls `collectSelectionIndices(input.selection, allTimestamps)` to get selectedIndices.
  4. Filters all arrays by selectedIndices into filteredData (timestamps, power, velocity, positionLat, positionLong, altitude, distance, windSpeed, temperature, cdaReference).
  5. If `calculateRhoArray` is provided and returns non-null, selects rho values by indices; otherwise rhoArray is null.
  6. Creates VE calculator and calls `calculateVirtualElevation` with the filtered arrays.
  7. Returns `{ filteredData, initialResult, selectedIndices, defaultAirSpeedOffset, rhoArray }`.
  8. Does NOT mutate any external state. Per D-05, the caller syncs rhoArray and other state.

- The function takes `getNormalizedActivityArrays` as an injected dependency so it can be tested with a mock. This function currently lives in main.ts and is not yet extracted, so injection is the cleanest seam.

**frontend/src/shell/analysis/renderDelegates.ts:**
- Import `ModeRenderCallbacks`, `StandardRenderArgs` from `../../modes/analysis/types`.
- Import `LapIndexRange`, `ActivityDataLike` from `../../state/AppState`.
- Import `OutAndBackSection` from `../../utils/GpsLapDetection`.
- Import `AnalysisParameters` from `../../components/AnalysisParameters`.

- Export `createStandardRenderDelegate(renderFn: (args: StandardRenderArgs) => Promise<void> | void): (args: StandardRenderArgs) => Promise<void> | void` — returns the provided renderFn directly, but wrapped in a named delegate. The wrapping adds a `log.debug` call before delegating to renderFn (using log from `../../utils/log`).

- Export `createGpsLapRenderDelegate(renderFn: (args: { lapIndexRanges: LapIndexRange[]; fitData: ActivityDataLike; params: AnalysisParameters; defaultAirSpeedOffset: number }) => Promise<void> | void)` — same pattern, wraps with debug log.

- Export `createOutAndBackRenderDelegate(renderFn: (args: { sections: OutAndBackSection[]; fitData: ActivityDataLike; params: AnalysisParameters; defaultAirSpeedOffset: number }) => Promise<void> | void)` — same pattern, wraps with debug log.

- Export `createModeRenderCallbacks(callbacks: { standard: (args: StandardRenderArgs) => Promise<void> | void; gpsLap: (args: any) => Promise<void> | void; outAndBack: (args: any) => Promise<void> | void }): ModeRenderCallbacks` — convenience factory that wraps each callback in its named delegate and returns a `ModeRenderCallbacks` object. This replaces the inline `callbacks: { standard: ..., gpsLap: ..., outAndBack: ... }` construction currently at main.ts line 2972.

The delegate pattern allows handleAnalyze to import `createModeRenderCallbacks` and pass the actual render functions (showVirtualElevationAnalysisInline, showGpsLapVEAnalysis, showOutAndBackVEAnalysis) as arguments, getting back a properly typed `ModeRenderCallbacks` object with named delegates instead of anonymous inline lambdas.

Per D-06, these delegates do NOT change analysis semantics. They are thin wrappers that add logging and provide named import points.
