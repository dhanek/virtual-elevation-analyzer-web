<task type="auto">
  <name>Task 2: Create tab-switching, slider/number sync, and action-footer helpers</name>
  <files>frontend/src/shell/dom/tabs.ts, frontend/src/shell/dom/tabs.test.ts, frontend/src/shell/dom/rangeNumberPair.ts, frontend/src/shell/dom/rangeNumberPair.test.ts, frontend/src/shell/dom/actionFooter.ts, frontend/src/shell/dom/index.ts</files>
  <read_first>frontend/src/main.ts, frontend/src/shell/dom/elements.ts, frontend/src/utils/log.ts</read_first>
  <action>
In `tabs.ts`:
- Export `function bindTabSwitching(container: HTMLElement | string, options: { onSwitch?: (tabId: string) => void }): void`.
  - Finds all `.ve-tab-button` elements inside the container.
  - On click: removes `active` class from all buttons, adds `active` to clicked one.
  - Hides all `.ve-tab-content` elements, shows the one matching `data-tab="{tabId}"`.
  - Calls `onSwitch` with the activated tab ID.
- Export `function setActiveTab(container: HTMLElement | string, tabId: string): void`.
  - Programmatically activates the tab matching `tabId` and shows its content.

In `tabs.test.ts`:
- Test `bindTabSwitching` with a mock DOM: verify `onSwitch` is called with the correct tab ID.
- Test `setActiveTab` correctly toggles `active` class and content visibility.
- Use `// @vitest-environment jsdom`.

In `rangeNumberPair.ts`:
- Export `function bindRangeNumberPair(rangeId: string, numberId: string, options?: { min?: number; max?: number; step?: number; onChange?: (value: number) => void }): void`.
  - Finds range and number inputs by ID.
  - On either input change: syncs the other input's value.
  - Optionally clamps to min/max.
  - Calls `onChange` with the new numeric value.
- Export `function setRangeNumberValue(rangeId: string, numberId: string, value: number): void`.
  - Programmatically sets both inputs to the given value and dispatches input events.

In `rangeNumberPair.test.ts`:
- Test that changing the range input updates the number input and vice versa.
- Test that `onChange` fires with the correct value.
- Test clamping behavior.
- Use `// @vitest-environment jsdom`.

In `actionFooter.ts`:
- Export type `ActionFooterHandlers = { onSaveScreenshot?: () => void; onStoreResult?: () => void; onExportAllResults?: () => void }`.
- Export `function bindActionFooter(container: HTMLElement | string, handlers: ActionFooterHandlers): void`.
  - Queries for `#saveScreenshot`, `#storeResult`, `#exportAllResults` inside the container.
  - Attaches click handlers from the provided callbacks.

In `index.ts`:
- Re-export everything from `elements.ts`, `selectableCards.ts`, `tabs.ts`, `rangeNumberPair.ts`, and `actionFooter.ts`.
