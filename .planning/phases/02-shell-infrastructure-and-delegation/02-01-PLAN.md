Create the directory frontend/src/shell/dom/ and two helper modules:

**frontend/src/shell/dom/elements.ts:**
- Export `getElement(id: string): T | null` — thin typed generic wrapper around `document.getElementById`.
- Export `getRequiredElement(id: string, context?: string): T` — calls `getElement`, throws Error with message including id and optional context if null. Use `log.error` from `../../utils/log` before throwing.
- Do NOT introduce any caching or singleton patterns.

**frontend/src/shell/dom/selectableCards.ts:**
- Export interface `SelectableCardItem` with fields: `{ id: string; label: string; details: string; checked: boolean; dataAttr: string; dataValue: string | number }`.
- Export `renderSelectableCards(items: SelectableCardItem[], cssClass: string): string` — pure function returning HTML string of checkbox-card items using the same `.lap-checkbox-item` / `.lap-info` / `.lap-number` / `.lap-details` DOM structure currently used in main.ts. The `cssClass` parameter becomes the checkbox CSS class (e.g., `'gps-lap-checkbox'`, `'oab-section-checkbox'`, `'lap-checkbox'`). Each card gets `data-${item.dataAttr}="${item.dataValue}"`.
- Export `bindSelectableCardEvents(container: HTMLElement, checkboxClass: string, dataAttr: string, onChange: (selectedValues: number[]) => void): void` — finds all checkboxes with `checkboxClass` within `container`, attaches `change` event that collects all checked values from `data-${dataAttr}`, and calls `onChange`. Also attaches click handlers on `.lap-checkbox-item` elements to toggle their checkbox and trigger onChange. This replaces the three nearly-identical binding blocks in updateGpsDetectedLapsUI, updateOutAndBackSectionsUI, and initializeSection3.
- Import `log` from `../../utils/log` for debug logging inside event handlers.

**frontend/src/shell/dom/selectableCards.test.ts:**
- Test `renderSelectableCards` returns correct HTML structure with items marked checked/unchecked.
- Test `renderSelectableCards` with empty array returns empty string.
- Test `renderSelectableCards` uses the correct CSS class and data attributes.
- For `bindSelectableCardEvents`, test that calling it on a container with rendered cards and simulating a checkbox change calls onChange with the correct selected values. Use `document.createElement('div')` + `innerHTML` to set up DOM in tests (jsdom via Vitest).

Do NOT import or depend on AppState. These helpers must be DOM-only and stateless.

Create four more helper modules and two test files:

**frontend/src/shell/dom/tabs.ts:**
- Export interface `TabRenderMap` with fields: `{ wind?: () => void; power?: () => void; vd?: () => void }`.
- Export `setupTabSwitching(renderMap: TabRenderMap): void` — finds `.ve-tab-button` elements, attaches click handlers that:
  1. Remove `active` from all `.ve-tab-button` elements, add `active` to clicked button.
  2. Remove `active` from all `.ve-tab-content` elements, add `active` to the tab content matching `data-tab` attribute (i.e., `${tabName}-tab`).
  3. Check `document.getElementById('wind-tab')` / `document.getElementById('vd-tab')` existence before calling optional renderMap callbacks.
  4. Call `renderMap[tabName]()` if it exists for the active tab.
- This replaces setupGpsLapTabSwitching, setupOutAndBackTabSwitching, and the inline tab block near line 4370.

**frontend/src/shell/dom/rangeNumberPair.ts:**
- Export interface `RangeNumberPairOptions` with fields: `{ rangeId: string; numberId: string; decimals?: number; clampMin?: number; clampMax?: number }`.
- Export `syncRangeAndNumber(options: RangeNumberPairOptions, onChange: (value: number) => void): void` — finds range and number inputs by their IDs, attaches `input` event on range and `change` event on number input, syncs values bidirectionally, clamps if min/max provided, formats to `decimals` decimal places (default 1), calls `onChange` with the new value.
- This replaces the repeated slider/number synchronization pattern found in setupVESliders, setupGpsLapSliderHandlers, and setupOutAndBackSliderSync.

**frontend/src/shell/dom/windSource.ts:**
- Export `getSelectedWindSource(): string` — queries `document.querySelector('input[name="windSource"]:checked')` and returns its `.value`, falling back to `'fit'`. This replaces the 13 scattered inline queries.
- Export `bindWindSourceRadios(onChange: () => void): void` — queries `document.querySelectorAll('input[name="windSource"]')`, attaches `change` listener calling `onChange`. This replaces the 3 identical wind-source binding blocks.

**frontend/src/shell/dom/actionFooter.ts:**
- Export interface `ActionFooterCallbacks` with fields: `{ onSaveScreenshot: () => void; onStoreResult: () => void; onExportAll: () => void }`.
- Export `bindActionFooter(callbacks: ActionFooterCallbacks): void` — looks up `saveScreenshot`, `storeResult`, `exportAllResults` by ID and attaches click handlers. Uses getElement (returns null-ok) and only binds if element exists. This replaces the 3 identical footer-binding blocks.

**frontend/src/shell/dom/tabs.test.ts:**
- Test setupTabSwitching with a mock DOM: render two tab buttons and two tab content divs, click a button, verify active classes toggled and renderMap callback invoked.

**frontend/src/shell/dom/rangeNumberPair.test.ts:**
- Test syncRangeAndNumber: create range and number inputs in a container, verify bidirectional sync, verify clamping, verify onChange callback receives correct value.

**frontend/src/shell/index.ts:**
- Barrel file re-exporting all shell/dom modules: `export * from './dom/elements'`, `export * from './dom/selectableCards'`, `export * from './dom/tabs'`, `export * from './dom/rangeNumberPair'`, `export * from './dom/windSource'`, `export * from './dom/actionFooter'`.

All modules must use `log` from `../../utils/log` for debug/warn logging, NOT raw `console.*`. No AppState imports.
